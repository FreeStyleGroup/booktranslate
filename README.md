# BookTranslate

Платформа перевода технической документации: разбор исходника до перевода,
единая терминология по всем томам, проверяемое качество на каждом сегменте.

Рабочее имя. Переименование репозитория и продукта на этом этапе стоит одну
кнопку — откладывать решение о названии не страшно.

## Почему новый репозиторий

Ранее было три независимые попытки (`Books`, `BookTranslate-AI`,
`BookTranslate-AI-Lab` в аккаунте `vorartjomworker-dotcom`), сделанные за пять
дней в августе 2026 и не связанные между собой. Их разбор — в
`D:\Claude\BookTranslate\AUDIT.md`. Ключевое из разбора:

- мультитенантности нет ни в одной из трёх — под SaaS её закладывают до
  переноса кода, а не после;
- на вход принимаются только `.docx` и `.epub`, а техдокументация приходит в
  PDF, HTML, Markdown и XLIFF — слой приёма всё равно строится заново;
- «глубокий анализ» там означает оценку перевода постфактум; анализа исходника
  до перевода нет, а именно он отличает продукт от обычного машинного перевода.

Поэтому продукт собирается заново, а старые репозитории остаются донорами
готовых кусков: парсеры документов, роутер моделей, память переводов и
глоссарий, проверки качества.

## Что внутри

```
apps/
  web/        Next.js 16 + React 19 (TypeScript) — витрина и будущее рабочее место
docs/         решения по архитектуре и их обоснование
```

Бэкенд появится в `apps/api` — стек выбирается отдельно, см.
`docs/DECISIONS.md`.

## Запуск витрины

```bash
cd apps/web
npm install
npm run dev        # http://localhost:3000
```

Проверки, которые гоняет CI:

```bash
npm run lint
npm run typecheck
npm run build
```

## Развёртывание

Витрина деплоится на Vercel из этого репозитория: Root Directory — `apps/web`.
Каждый push в `main` уезжает в продакшен, каждая ветка получает превью-ссылку.

Проект на Vercel: `booktranslate` в аккаунте `freestyletravel` — отсюда
`freestyletravel` в адресах вида
`booktranslate-<хеш>-freestyletravel.vercel.app`: Vercel подставляет в них
slug аккаунта, а не имя проекта.

⚠️ По умолчанию Vercel закрывает деплои своей авторизацией: посторонний
получает редирект на `vercel.com/sso-api`, а не страницу. Пока витрину нужно
показывать без входа в Vercel — Project Settings → Deployment Protection →
Vercel Authentication → Disabled (для Production; на превью защиту разумно
оставить).

Бэкенд на Vercel не поедет — ему нужны постоянные процессы, очередь и база;
он развернётся на отдельном сервере, а витрина будет ходить к нему по адресу
из `NEXT_PUBLIC_API_URL`.
