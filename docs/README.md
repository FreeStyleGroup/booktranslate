# Документация

Карта: что где искать. Каждый документ отвечает на один вопрос и
обновляется вместе с кодом, а не задним числом.

| Документ | Отвечает на вопрос |
|---|---|
| [JOURNAL.md](JOURNAL.md) | Что делалось, в каком порядке и почему. Читать первым, если вернулись к проекту после перерыва |
| [DECISIONS.md](DECISIONS.md) | Почему выбран этот стек и подход, что осталось нерешённым |
| [DATA_MODEL.md](DATA_MODEL.md) | Из чего состоит предметная область: организации, проекты, документы, сегменты |
| [CI_CD.md](CI_CD.md) | Как код проверяется и попадает на боевые адреса |
| [../CONTRIBUTING.md](../CONTRIBUTING.md) | Как вести ветки, коммиты и PR; какой код принимается |
| [../apps/api/README.md](../apps/api/README.md) | Как поднять и проверить бэкенд |
| [../README.md](../README.md) | Что это за проект и как запустить витрину |

## Правило

Изменил поведение или устройство — правишь документ в том же pull request.
Документация, отставшая от кода, хуже отсутствующей: по ней принимают
решения, считая её верной.

Новый этап работы — запись в `JOURNAL.md`: что сделано, что осталось
открытым. Принял решение, которое кто-то захочет оспорить через месяц, —
запись в `DECISIONS.md` с причиной.

## Сборка

Файлы GitHub Actions лежат на своём месте, в `.github/workflows`. Каталога
`docs/ci/` больше нет: он был обходом на время, пока у токена разработки не
было права `workflow`.
